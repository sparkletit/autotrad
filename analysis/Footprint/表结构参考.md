## Calls（函数调用）

### `bsc_decoded_calls`
已解码的智能合约函数调用

| 字段名 | 类型 | 说明 |
|-------|------|------|
| `block_number` | BIGINT | 区块号 |
| `block_timestamp` | TIMESTAMP | 区块时间戳 |
| `contract_address` | VARCHAR | 合约地址 |
| `contract_name` | VARCHAR | 合约名称 |
| `decoded_data` | JSON | 解码后的调用参数 |
| `function_name` | VARCHAR | 函数名称 |
| `protocol_slug` | VARCHAR | 协议标识 |
| `transaction_hash` | VARCHAR | 交易哈希 |
| `transaction_index` | INT | 交易在区块中的索引 |
| `version` | VARCHAR | 版本号 |

**示例查询**：
```sql
SELECT 
    transaction_hash,
    contract_name,
    function_name,
    decoded_data
FROM bsc_decoded_calls
WHERE block_timestamp >= CURRENT_DATE - INTERVAL '1' DAY
    AND function_name = 'swapExactTokensForTokens'
LIMIT 10;
```

## DeFi

### `defi_protocol_daily_stats` 🔬 Beta
DeFi 协议每日统计数据

**说明**：该表仍在 Beta 阶段，字段和数据可能发生变化。

**使用建议**：适用于协议级别的宏观数据分析。

---

### `dex_pool_info` 🔬 Beta
DEX 交易对/池子信息

**关键字段**（推测）：
- `pool_address` - 池子地址
- `protocol_slug` - DEX 协议名称
- `token0_address` - Token0 地址
- `token1_address` - Token1 地址
- `created_time` - 创建时间
- `chain` - 链名称（多链表需过滤）

**示例查询**：
```sql
SELECT 
    pool_address,
    protocol_slug,
    token0_address,
    token1_address,
    created_time
FROM dex_pool_info
WHERE chain = 'bsc'
    AND created_time >= CURRENT_DATE - INTERVAL '30' DAY
LIMIT 100;
```

**注意**：Beta 版本，建议先小范围测试。

### `dex_trades` 🔬 Beta
DEX 交易记录

**说明**：包含 DEX 的 Swap/交换交易详情。

**关键字段**（推测）：
- `transaction_hash` - 交易哈希
- `block_timestamp` - 交易时间
- `pool_address` - 池子地址
- `token_in` - 输入代币
- `token_out` - 输出代币
- `amount_in` - 输入金额
- `amount_out` - 输出金额
- `trader` - 交易者地址

**示例查询**：
```sql
SELECT 
    transaction_hash,
    block_timestamp,
    pool_address,
    trader,
    token_in,
    token_out,
    amount_in,
    amount_out
FROM dex_trades
WHERE chain = 'bsc'
    AND block_timestamp >= CURRENT_DATE - INTERVAL '1' DAY
LIMIT 10;
```

## Token（代币）

### `token_info`
代币基本信息（多链）

**关键字段**：
- `token_address` - 代币合约地址（⚠️ 注意：不是 `address`）
- `symbol` - 代币符号
- `name` - 代币全名
- `decimals` - 小数位数
- `chain` - 所在链

**示例查询**：
```sql
SELECT 
    token_address,
    symbol,
    name,
    decimals
FROM token_info
WHERE chain = 'bsc'
    AND symbol IN ('WBNB', 'USDT', 'USDC', 'BUSD')
LIMIT 10;
```

**⚠️ 重要**：这是多链表，必须加 `WHERE chain = 'bsc'` 过滤！

## Chains（链信息）

### `bsc_blocks`
BSC 区块信息

**关键字段**：
- `number` / `block_number` - 区块号
- `timestamp` / `block_timestamp` - 区块时间
- `hash` - 区块哈希
- `parent_hash` - 父区块哈希
- `miner` - 矿工地址
- `gas_used` - 使用的 Gas
- `gas_limit` - Gas 限制

---

### `bsc_logs`
BSC 原始事件日志

**关键字段**：
- `block_number` - 区块号
- `block_timestamp` - 区块时间
- `transaction_hash` - 交易哈希
- `log_index` - 日志索引
- `address` - 合约地址
- `topics` - 事件主题（数组）
- `data` - 事件数据（十六进制）

**使用场景**：低级事件分析、未解码事件查询。

---

### `bsc_token_transfers` ⭐️ 重要
BSC ERC20 代币转账事件

**关键字段**：
- `transaction_hash` - 交易哈希
- `block_number` - 区块号
- `block_timestamp` - 区块时间
- `token_address` - 代币合约地址
- `from_address` - 发送方
- `to_address` - 接收方
- `value` - 转账金额（原始值，需除以 decimals）

**示例查询**：
```sql
-- 查询某个池子的流出事件
SELECT 
    transaction_hash,
    block_timestamp,
    token_address,
    from_address,
    to_address,
    value
FROM bsc_token_transfers
WHERE from_address = '0x...'  -- 池子地址
    AND block_timestamp >= CURRENT_DATE - INTERVAL '1' DAY
LIMIT 100;
```

**性能优化**：
- 必须使用 `block_timestamp` 或 `block_number` 过滤
- 避免 `value > 0` 作为唯一过滤条件
- 使用 LIMIT 限制返回数量

### `bsc_traces`
BSC 交易追踪（内部调用）

**说明**：记录交易的内部调用（internal transactions）。

**使用场景**：追踪合约间的调用关系、检测间接转账。

---

### `bsc_transactions` ⭐️ 重要
BSC 链上交易

**关键字段**：
- `hash` - 交易哈希
- `block_number` - 区块号
- `block_timestamp` - 区块时间
- `from_address` - 发起方
- `to_address` - 接收方（合约或 EOA）
- `value` - 转账金额（BNB，单位：Wei）
- `gas` - Gas 使用量
- `gas_price` - Gas 价格
- `receipt_status` - 交易状态（1=成功，0=失败）
- `input` - 交易输入数据

**示例查询**：
```sql
-- 查询成功的交易
SELECT 
    hash,
    block_timestamp,
    from_address,
    to_address,
    value,
    gas,
    gas_price
FROM bsc_transactions
WHERE block_timestamp >= CURRENT_DATE - INTERVAL '1' DAY
    AND receipt_status = 1
LIMIT 10;
```

**注意事项**：
- `value` 单位是 Wei（1 BNB = 10^18 Wei）
- `receipt_status = 1` 表示成功，`= 0` 表示失败

## Events（事件）

### `bsc_decoded_events`
已解码的事件日志

**关键字段**：
- `block_number` - 区块号
- `block_timestamp` - 区块时间
- `transaction_hash` - 交易哈希
- `log_index` - 日志索引
- `contract_address` - 合约地址
- `event_name` - 事件名称
- `decoded_data` - 解码后的事件参数（JSON）

**示例查询**：
```sql
-- 查询所有 Transfer 事件
SELECT 
    transaction_hash,
    block_timestamp,
    contract_address,
    event_name,
    decoded_data
FROM bsc_decoded_events
WHERE event_name = 'Transfer'
    AND block_timestamp >= CURRENT_DATE - INTERVAL '1' DAY
LIMIT 10;
```

**优势**：比 `bsc_logs` 更易读，已经解析好参数。

## 🔍 查询技巧

### 1. 多链表必须过滤 chain
```sql
-- ✅ 正确
SELECT * FROM token_info WHERE chain = 'bsc';
SELECT * FROM dex_pool_info WHERE chain = 'bsc';

-- ❌ 错误（会查询所有链）
SELECT * FROM token_info WHERE symbol = 'USDT';
```

### 2. 时间过滤是性能关键
```sql
-- ✅ 好性能
WHERE block_timestamp >= CURRENT_DATE - INTERVAL '7' DAY

-- ⚠️ 慢查询
WHERE block_timestamp >= '2023-01-01'  -- 范围太大

-- ❌ 极慢
WHERE value > 1000  -- 没有时间过滤
```

### 3. JOIN 优化
```sql
-- ✅ 先过滤再 JOIN
WITH filtered_transfers AS (
    SELECT * FROM bsc_token_transfers
    WHERE block_timestamp >= CURRENT_DATE - INTERVAL '1' DAY
)
SELECT t.*, tk.symbol
FROM filtered_transfers t
LEFT JOIN token_info tk ON t.token_address = tk.address;

-- ❌ 先 JOIN 再过滤（可能很慢）
SELECT t.*, tk.symbol
FROM bsc_token_transfers t
LEFT JOIN token_info tk ON t.token_address = tk.address
WHERE t.block_timestamp >= CURRENT_DATE - INTERVAL '1' DAY;
```

### 4. 使用 LIMIT 保护
```sql
-- ✅ 始终添加 LIMIT
SELECT * FROM bsc_token_transfers
WHERE block_timestamp >= CURRENT_DATE - INTERVAL '1' DAY
LIMIT 1000;

-- ❌ 没有 LIMIT 可能返回百万行
SELECT * FROM bsc_token_transfers
WHERE block_timestamp >= CURRENT_DATE - INTERVAL '1' DAY;
```
